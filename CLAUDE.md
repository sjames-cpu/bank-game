# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

**BankSim** is a Godot 4.7 bank-branch simulation written entirely in GDScript (the project is configured for .NET, but there are no C# scripts, `.csproj` or `.sln`). The player starts as a Teller, unlocks Loan Officer and then Branch Manager, works alongside NPC coworkers, and can be disciplined and fired. `HANDOFF.md` (the original bug list and roadmap) and `AUDIT_REPORT.md` (an audit of the first fixes) drive the current work; both have a status note at the top. `DEVLOG.md` records how the project got here, session by session.

Keep this file in step with the code: update it when structure or behaviour changes.

## Flow

`run/main_scene` is the start screen (`scenes/ui/start_screen.tscn`, `StartScreen`): the **main menu** ("Play", "Quit") and, behind Play, the **save slot screen**: `SaveGame.SLOT_COUNT` (3) slots and "Back". A filled slot shows the career's role, in-game day and date (`StartScreen.game_date_of()`) and "Last played" (the save's `saved_at`), and loads that career; an empty one shows "New Game" and starts a career in it; a damaged or other-version save says so and offers a new game there, with the bad file set aside. A filled slot also has Delete, which asks "Delete this save? This cannot be undone." and then deletes that slot only (`SaveGame.delete_slot()`, the same `delete()` termination uses). The whole branch is one room, `scenes/world/teller_room.tscn`, where every role works. In the room, **Esc** opens the pause menu (`pause_menu.gd`, `PauseMenu`, the `pause_menu` action): Resume, and Back to Main Menu, which saves first off shift and, clocked in, asks first and doesn't save ("Progress since your last save will be lost": a career is never saved mid-shift). It opens only while nothing else has the tree paused (no desk screen, letter or summary up).

**No leftover state**: the start screen unpauses, leaves the slot (`SaveGame.leave_slot()`) and runs `CareerReset.reset_all()` whenever it opens; loading a slot restores into a fresh career (`SaveGame.restore()`), and a new game resets again. The pause menu and the termination letter also leave the slot and reset before changing scene. Anything new that holds career state across scenes must be reset there too (see Autoloads).

**The interview switch** (`InterviewManager.INTERVIEW_ENABLED`, currently **false**): the hiring interview is temporarily off while it's redesigned. Nothing of it was removed (scene, questions, outcomes, probation); setting the constant to `true` brings back the old flow. The game reads it through `InterviewManager.interview_enabled`, which tests set to cover both ways (`teller_room_suite.use_interview_setting()`; it isn't career state).
- **Off (now)**: a new game in an empty slot resets the career, hires the player as a regular Teller with no probation (`InterviewManager.hire_without_interview()`), saves into that slot, and loads the room. Termination (see Reports) is game over: the letter adds `DisciplineLetterScreen.GAME_OVER_TEXT`, and its button, "Back to Save Slots", wipes all career progress (`CareerReset.reset_all()`, which calls each autoload's `reset()`) and opens the slot screen (`StartScreen.next_view`), where the cleared slot shows New Game. A saved career already on probation keeps it.
- **On**: a new game in an empty slot goes to the hiring interview (`scenes/ui/interview_screen.tscn`), whose hire saves into that slot. Hired or Hired on Probation loads the room; Rejected restarts the interview. Termination's button is "Apply for a new job": it wipes the career and loads the interview again, in the same slot.

Desk screens pause the tree while open (`get_tree().paused = true`), so customers, staff and the room's `_process` stop; the HUD, letters and the day/night tint run with `process_mode` ALWAYS.

## The room (`scenes/world/teller_room.tscn`, `scripts/world/`)

- **Layout** (`room_builder.gd`, built at runtime on a 24×22-tile `TileMapLayer`, 32 px tiles): a back-office row along the top (Vault, Manager's Office, Conference Room, Accounting), each with a door gap into one open floor below (Marketing + Loan bullpen on the left, the three teller windows in the middle, the Waiting Lounge and ATM near the entrance). The entrance gap in the bottom wall is a doormat, and a solid sidewalk strip runs outside it (second atlas `assets/tilesets/outdoor_tiles.png`), so the player can stand in the doorway but not leave. The player spawns at (384, 624), just inside the entrance.
- **Desks**: the player's own **Player Teller Window** (`TellerDesk`, x=464, its own `CustomerQueue` lane); **Teller Window 1/2** (x=560/656, always staffed); three loan desks: **Loan Desk 1** (`LoanOfficerDesk`, x=208, the player's as Loan Officer, staffed while they aren't working it) between **Loan Desk 2** and **Loan Desk 3** (`Decor/LoanDesk2`/`LoanDesk3`, x=112/304, decor desks with a `StaffSpot`, always staffed); the **Branch Manager desk** in the Manager's Office (hidden until promotion); the **ATM**; and the **vault door** (`VaultDoor`, inside the Vault room, see The vault door below). The usable ones extend `Interactable` (`interactable.gd`: `signal interacted`, `player_in_range`, fires on `ui_accept` or the `interact` action, E) with class_names `TellerDesk`, `LoanOfficerDesk`, `BranchManagerDesk`, `ATM`, `VaultDoor` (and the entrance's `ExitDoor`). They know nothing about what happens next; `teller_room.gd` (`TellerRoom`) connects their signals, gates them (Loan Desk 1 until the unlock, everything staffed after promotion) and opens the screens.
- **Draw order and collision (B5)**: the room root is y-sorted, as are `Staff`, the customer lines, `Decor` and each desk node, so the player, customers, staff and furniture sort together. Each furniture sprite's origin is its base (texture `offset` up), so characters switch from behind to in front where their feet pass its bottom edge; staff stand above their counter's base so it covers their lower body. Solid furniture has a `Footprint` `StaticBody2D` covering only its base, on physics layer 16. Only the player's mask (17 = walls + furniture) includes it. Customers and staff walk scripted paths and collide with walls only, and the player and NPCs never collide: a customer walks through a player standing in their lane. The hidden Branch Manager desk's footprint is disabled until promotion.
- `player_movement.gd` (`PlayerMovement`): 8-direction `CharacterBody2D` movement through the `move_*` actions (WASD + arrows), 4-direction idle/walk animation. `day_night_cycle.gd`: a purely visual `CanvasModulate` tint driven by the game clock (`colour_at()`): night until 6 AM, full daylight 8 AM-3 PM, warmest at 5 PM, night again from 7:30 PM.
- **Camera** (`room_camera.gd`, `RoomCamera`, on the player's `Camera2D`): a 2x view that follows the player smoothly, clamped to the room (`teller_room.room_bounds()`: the 24x24-tile room plus sidewalk, 768x768 px), so no empty space shows past the walls. `toggle_overview` (Z, named in the arrival hint) switches to the 1x overview, the room's old zoom, which is wider than the room, so the room is centred horizontally; at 648 px high it shows about 85% of the room's height and follows the player vertically. World-space text (staff names and speech, customer farewells and requests) goes through `WorldText`: each label is rasterised at its on-screen size and scaled by 1/zoom, so it stays crisp. It's 11–12 px on screen at 1x and 1.25x that at 2x, anchored at the same point above the character. The HUD, screens and letters are on CanvasLayers and don't zoom; the interaction prompt converts its world position through the canvas transform.

## Autoloads (`scripts/autoload/`, registered in `project.godot`)

Each has `reset()`, called by `CareerReset`, and `save_data()`/`load_data()`, called by `SaveGame` (see Save and load); any new autoload holding career progress needs all three, plus lines in `CareerReset.reset_all()` and `SaveGame.capture()`/`restore()`.

- **GameClock**: the bank's game clock: `day` (from 1) and `minutes` since midnight. A new career starts on Day 1 at 8:30 AM. It runs only while the tree isn't paused (desk screens and letters stop it, like NPC work) at `GAME_MINUTES_PER_SECOND` (1.5): a 4-customer teller shift, about 90 s of unpaused time, is about 2¼ game hours, so four shifts fill 9 AM-5 PM. Days end at the End of Day summary (see BusinessDay); rolling past midnight is only a fallback. `timestamp()` ("Day 3, Wed 7 Jan, 10:42 AM"; `day_of()` reads the day back, old "Day 3, 10:42 AM" stamps too) stamps history records, reports, review items, teller transactions and the shift summaries' start and end times; `hud_text()` ("Wed, Day 3 · 10:42 AM") tops the HUD. **Calendar** (`scripts/util/bank_calendar.gd`, `BankCalendar`, static date arithmetic on epoch days, no wall clock): "Day N" is the career's Nth *business* day, from `start_date` (Day 1, `BankCalendar.start_date()`: Monday 5 January 2026, saved as an ISO date with the clock) through each next business day (`date_of_day()`, `today_date()`), so weekends and holidays never get a day number. The branch is closed Saturday, Sunday and on the Federal Reserve's bank holidays (`holidays_in()`: New Year's Day, Birthday of Martin Luther King, Jr., Washington's Birthday, Memorial Day, Juneteenth National Independence Day, Independence Day, Labor Day, Columbus Day, Veterans Day, Thanksgiving Day, Christmas Day), observed the Federal Reserve's way: a Sunday holiday moves to Monday ("(observed)"), a Saturday one isn't moved (open the Friday before). The only wall-clock time left is the save file's `saved_at`, shown on the slot screen as "Last played".
- **BusinessDay**: the opening hours and the day's totals. Open 9:00 AM-5:00 PM (`is_open()`): customers arrive only then, at the player's and staff lines' spawn timers, and the loan desks' staff decide only then. At 9:00 every line taking customers restarts its spawn timer (`CustomerQueue.open_for_the_day()`, called by `teller_room.gd` as the branch opens), so its first customer comes 1.5–4.5 game minutes after opening. Clock-in at any desk is refused after 4:30 PM (`can_start_shift()`); the player may clock in early from 8:30 for the opening count. At 5:00 PM the doors close (`doors_closed()`): customers inside are still served, staff finish theirs and idle, and customers the player's shift never got don't block clock-out (`teller_room.customers_still_to_arrive()`, the HUD's "Branch closed — no more customers today"). Several shifts fit in a day. Once it's past 5:00 PM, the player is off shift and the lobby is empty, `teller_room.gd` shows the End of Day summary (`end_of_day_screen.gd`): the date ("Friday 9 January 2026"), customers the branch served today (player and staff), the player's shifts, today's Score, Reputation and XP changes, the vault's day (`EndOfDayScreen.vault_text()`: staff windows' net, ATM restock, deliveries and shipments, the total against its limits, and the NPC branch manager's order), and today's teller transactions after the cutoff. "Start Day N+1" (`start_next_day()`) sets the clock to 8:30 AM the next business day; when that's after a weekend or holiday (`closures_before_next_day()`), the button first turns the panel into the closure notice (`is_closure_shown()`): "Weekend — the branch is closed" (or the holiday's name, `BankCalendar.closure_title()`), each closed date and when the branch reopens, and pressing it again starts the day. **Cutoff** (`CUTOFF_MINUTES`, 2:00 PM): a teller transaction from then on posts on the next business day (`posting_day()`, recorded as `ShiftTransaction.posting_day`); the teller screen shows "After cutoff — posts Mon 12 Jan" (`cutoff_label`, `cutoff_text()`), and the teller's clock-out adds the shift's late ones to `after_cutoff` (saved) for the summary (up to 6 lines). Balances, grading and the drawer change at once as before. Off shift, the entrance doormat (`ExitDoor`, "E — Go home (end Day N)") asks "Go home and end Day N?"; going home (`go_home_early()`) skips the clock to 5:00 PM, clears the lobby and shows the same summary, with nothing simulated for the skipped hours. Saved with the career; the career is saved when the summary appears and when the next day starts. A one-time hint (`Hint.OPENING_HOURS`) explains the hours and going home.
- **AccountManager**: the shared `Account` list (Teller, ATM and staff lines all use it). `create_account()`, `deposit()`/`withdraw()` (cents), `get_browsable_accounts()` (hides auto-created customer accounts from the teller dropdown), `find_account_by_name(name, staff_line)` (the player's line and the staff lines are separate namespaces, so staff work never moves a player-line customer's balance). Seeds a $1,000 demo account.
- **VaultManager**: the branch vault's expected cash (`expected_cents`, int cents) and its supply chain, part 1 (part 2 will add the armored truck). It starts at `VaultReconciliationScreen.STARTING_VAULT_CENTS` ($200,000) and should stay within `VAULT_MIN_CENTS` $100,000 and `VAULT_MAX_CENTS` $300,000 (`limit_warning()`: "Vault low — order cash from the Federal Reserve", "Vault over limit — ship excess cash to the Federal Reserve"; the minimum covers about two weeks of ATM restocks plus refilling the teller drawers, the maximum caps idle cash at 1.5× the starting total). It moves by the teller's vault transfers (`receive_from_drawer()`, `pay_to_drawer()`, never below zero); by each business day's close (`close_day()`, once a day, when the End of Day summary appears: the staff windows' net cash, `BusinessDay.staff_net_cash_cents`, cash only, from real staff services; every `ATM_RESTOCK_EVERY_DAYS` (3) business days an ATM restock of `ATM_RESTOCK_CENTS` $24,000, for a machine paying out about $8,000 a day); and by cash orders from the Federal Reserve Bank, in straps of $10,000 (`STRAP_CENTS`), one a day (`place_order()`, cents > 0 in, < 0 shipped out, never more than the vault holds), arriving at opening on the next business day (`receive_deliveries()`, from the room at 9:00, or at the close as a fallback). Day numbers count business days only, so the next business day is always day + 1 across weekends and holidays. `forecast_for_tomorrow()` adds what's known (today's arrivals, staff net and restock if today hasn't closed, tomorrow's arrivals and restock). Before promotion an NPC branch manager orders at each close (`_npc_order()`): up to the middle ($200,000) when tomorrow's forecast is below the minimum, or down to it when above the maximum, each with `NPC_BUFFER_CENTS` (one strap) to spare, since its forecast leaves out tomorrow's staff swing. A close outside the limits is recorded (`out_of_range_days`, for part 2's Regional review). Saved with the career (`pending_orders`, `last_order_day`, `out_of_range_days`, `last_closed_day`, today's deliveries and the last close's figures; an older save has the starting total and nothing pending).
- **ScoreManager** / **ReputationManager**: career Score, and Reputation clamped to [0, 100] starting at 50 (`LOW_REPUTATION_THRESHOLD` 0 shows the HUD warning). Falling to 0 through `add_reputation()` emits `reputation_reached_zero` once (see Reports and Regional Manager); `zero_armed` re-arms it only once Reputation is above `LOW_REPUTATION_THRESHOLD`, and is saved (a save without it is armed unless saved at 0).
- **XPManager**: XP (10 per Score point, floored at 0) and the role unlocks. Loan Officer: 500 XP and 40 Reputation; Branch Manager: 1500 XP and 60 Reputation (after a demotion, `REPROMOTION_XP` 500 more than the XP at demotion: `repromotion_xp_target`, `branch_manager_xp_required()`). Checks run on XP and Reputation changes and fire once per promotion. `demote_branch_manager()` (from RegionalManager) clears the Branch Manager unlock and emits `branch_manager_demoted`. A Branch Manager unlock earned while clocked in at the Player Teller Window or Loan Desk 1 (`begin_player_shift()`/`end_player_shift()`) is held until clock-out. Also holds `has_seen_branch_orientation`.
- **InterviewManager**: holds the interview switch (`INTERVIEW_ENABLED`, `interview_enabled`; see Flow; while it's off, nothing below except an already-saved probation is reached), resolves the interview (`resolve_outcome()`: `HIRE_THRESHOLD` 15, `PROBATION_THRESHOLD` 5 out of 30 over 10 questions in `InterviewQuestionsData`; some answers are instant rejects) and owns probation. While `is_on_probation`, `report_limit()` is 2 (`PROBATION_REPORTS_FOR_TERMINATION`) instead of 3; `teller_room.gd` reports teller clock-in/out (`begin_teller_shift()`/`end_teller_shift()`), and 3 completed teller shifts with no new report (`PROBATION_CLEAN_SHIFTS`) end probation with a "Probation Complete" letter (`probation_completed`). A report (`note_report()`, from ReportManager) restarts the count; promotion to Branch Manager ends probation silently. Plain Hired has no probation.
- **HistoryManager**: log of `DecisionRecord`s. Roles: TELLER and LOAN_OFFICER (the player's work; actionable in Approvals), BRANCH_MANAGER, DISCIPLINARY and DRAWER_VARIANCE (record only), STAFF (NPC work: only the newest 200 kept, announced via `staff_record_added`, hidden from Approvals).
- **ScheduleManager**: which `StaffMember` (from `StaffRosterData`, with speed/skill/reliability stats) works each desk slot (`DESK_SLOTS`: Teller Window 1, Teller Window 2, Loan Desk 1, Loan Desk 2, Loan Desk 3 (`LOAN_DESK_SLOTS`, `is_loan_slot()`); Teller Window 3 joins after promotion). The six starting staff (three tellers, three loan officers) fill every desk, Teller Window 3 included. Saved with `slots_version` 2: an older save's "Loan Desk" (`LEGACY_SLOT_LOAN_DESK`, also in hiring vacancies) becomes Loan Desk 1 (`current_slot_name()`), and its Loan Desks 2 and 3 get the first unassigned Loan Officers. `dismiss_staff()` for terminations. The roster (`get_roster()`) is `StaffRosterData` plus `hired_staff`, minus dismissed staff, capped at `MAX_ROSTER_SIZE` (8); `vacant_slots()` lists unassigned desks and `hire_staff()` fills one.
- **StaffReviewManager**: the Branch Manager's staff review queue (see Branch Manager below).
- **HiringManager**: vacancies, job candidates, their interviews and hiring (see Branch Manager below).
- **HintManager**: which first-run hints this career has seen (`Hint`: arrival, first customer, first clock-out, Loan Officer and Branch Manager unlocks, opening hours, the first customer needing ID, the drawer's first time over its limit, the first use of the vault door) and their text.
- **RegionalManager**: the Regional Manager's review of the Branch Manager: the schedule, the review window's data, the rating, regional warnings and demotion (see Regional Manager below). Registered after BusinessDay and the managers it listens to.
- **ReportManager**: the player's disciplinary record (see Reports below). Registered last: it connects to XPManager in `_ready()`.

## Money (B3)

Every amount the player handles is **int cents** end to end: `Account.balance_cents`, `ShiftTransaction.amount_cents`, `CustomerNPC.intent_amount_cents`, drawer and vault expected/counted totals, ATM amounts, `TellerScreen.STARTING_FLOAT_CENTS` ($3,000), `VaultReconciliationScreen.STARTING_VAULT_CENTS` ($200,000, the vault's starting total; `VaultManager` tracks it from there). **Cash** (`scripts/util/cash_denominations.gd`, `CashDenominations`): current US notes and coins, `DENOMINATION_CENTS` = $100, $50, $20, $10, $5, $1, quarters, dimes, nickels, pennies, shared by both count screens, which build their rows from it (`build_grid()`: bills left, coins right). `fewest_pieces()` (greedy, optimal for US cash) gives the plausible minimum. The teller float is `STARTING_FLOAT_MIX` (5×$100, 6×$50, 75×$20, 40×$10, 45×$5, 40×$1 and two rolls of each coin, $35), and a drawer count's excess-piece check is measured against the larger of the fewest pieces and `TellerScreen.drawer_plausible_pieces()` (the float's pieces plus the fewest for any net cash taken in), so counting the float as it came stays Perfect. A cash withdrawal can't exceed the drawer's cash (`drawer_cash_cents()`, "Not enough cash in the drawer"); a full shift of the largest requests (4 × $500) never reaches it. Dollars appear only at the edges: `MoneyMath.to_cents()` once when a SpinBox value is entered, and `MoneyMath.format(cents)` ("$1234.50", "$-10.00") or `MoneyMath.format(cents, true)` ("$500" for whole dollars, for what people say) for every display. Loan application figures stay whole-dollar floats on purpose: they're judged, never moved as cash (see `loan_application.gd`).

## Teller (`scripts/ui/teller_screen.gd`, `TellerScreen`)

- **Clock-in / opening count (B2)**: the drawer is counted (`drawer_count_screen.gd`, `DrawerCountScreen`: Perfect needs an exact total and at most 4 more pieces (bills and coins) than the plausible count; Minor is within $50 (`MINOR_DISCREPANCY_THRESHOLD_CENTS`, half the largest note) and 15 extra pieces; otherwise Major. The vault's are 10× those: $500, 40 and 150 pieces). Perfect starts the shift; Minor starts it and logs a DRAWER_VARIANCE record; Major blocks it until a recount ("Recount Drawer", up to `MAX_OPENING_RECOUNTS` 2). Still Major after both, a supervisor signs off (−2 Reputation, logged) and the shift starts. The drawer always starts at the assigned float; the opening count earns no Score or XP.
- **Customers**: the player's line (`CustomerQueue`, `scripts/world/customer_queue.gd`) brings 4 customers per shift (`CUSTOMERS_PER_SHIFT_CAP`), each with their own account and a stated request (a round $10, $20–$500; withdrawals capped by their balance), 20% complaints, 50% paying by card (card transactions skip the drawer and can be declined, 10%). Customers wait 50 s before abandoning (−3 Score, −2 Reputation). **Staffing sets the pace**: customers choose a line, so the gap between arrivals (`CustomerQueue.spawn_interval`, 20 s) shrinks with how busy Teller Windows 1 and 2 are (`teller_room.staff_window_pressure()`, the average of each line's `NpcCustomerLine.crowding()`: a closed window 1, an open one 0 with nobody waiting behind the customer at the window, up to 1 with its line full). The gap is `20 × (1 − 0.5 × pressure)` (`MIN_INTERVAL_SHARE`), from 20 s for a fully staffed branch whose staff keep up down to 10 s, chosen as each gap starts (`CustomerQueue.arrival_pressure`). Queue movement is visual only: each customer holds a spot, steps forward into clear spots, and leaves sideways down a corridor between lanes.
- **Requests and Complete Transaction (B6)**: any number of deposits/withdrawals (and Reverse Transaction) for the customer at the desk, then **Complete Transaction** grades the net effect on their own account. Correct: +5 Score (+50 XP). Wrong: −3 Score, −2 Reputation and a mistake toward reports (once per customer); the customer says what's wrong and waits for a fix. A transaction on someone else's account must be reversed. Closing the screen completes open transactions; leaving a mistake unfixed sends the customer off upset (−3 more Reputation). Complaint customers are served by picking a response.
- **ID checks (KYC)** (`scripts/util/kyc_policy.gd`, `KycPolicy`; `scripts/data/id_card.gd`, `IdCard`): presented in game as bank policy, not as any law. Every player-line customer carries a photo ID (`CustomerNPC.id_card`: name, date of birth, ID number, expiry, and a portrait of a look, `CustomerNPC.look_index`), issued at spawn from the line's own `CustomerQueue.kyc_rng` (never the global RNG, so seeded draws elsewhere didn't change). `ID_PROBLEM_CHANCE` (1 in 7) of IDs have a problem, picked by `PROBLEM_WEIGHTS` (expired 3, name mismatch 2 (same first name, another surname), wrong portrait 2 (another design's look), no ID 1). ID is required for withdrawals (cash or card) and opening an account (`requires_id()`); deposits don't need it. **Check ID** (in the Complete Transaction row) shows the card in `IdCardPanel`, left of the main panel, beside the customer's own portrait, with today's date and the policy; **Refuse Service** ("I'm sorry, I can't process this without valid ID.") is on the card, for an ID-requiring request once checked and with nothing from the visit standing. The ID part is graded once, at the first Complete Transaction or at the refusal (`TellerScreen.KYC_*`): valid ID checked first, request done: the usual +5; bad ID refused: +5, "Good catch"; request done on a bad ID (checked or not): −8 Score, −3 Reputation and 2 mistakes toward reports (a written warning at once); request done without checking a valid ID first (`id_check_skipped`, set by the first transaction or account opening before Check ID; checking later doesn't undo it): −3 Score and 1 mistake; valid ID refused: −3 Score, −3 Reputation, the customer leaves upset (no mistake). An ID mistake replaces the correct reward, and adds to a wrong request's penalty. Staff lines (`NpcCustomerLine._checks_ids()`) and the ATM don't check ID. A one-time hint (`Hint.ID_CHECK`) comes with the first customer at the desk who needs ID.
- **Account opening**: `ACCOUNT_OPENING_CHANCE` (1 in 10) of regular customers come to open an account ("I'd like to open an account with $200.", `CustomerNPC.opens_account`), with a name that has no account yet and `account` null. The player checks ID, opens the account in their name with Open New Account (letter case aside; it's then their account, `is_customer_account`), and deposits the amount (a Starting Deposit counts as that deposit, into the drawer); Complete Transaction grades it all. An account in another name doesn't count ("I still need an account opened in my name").
- **Drawer limits and the vault** (`DRAWER_MAX_CENTS` $3,350, `DRAWER_MIN_CENTS` $1,000): the drawer's cash (`drawer_cash_cents()`: float + net cash − sold to the vault + bought from it; card transactions never count) shows in a `DrawerPanel` right of the main panel (clear of the HUD column) while clocked in, with "Drawer over limit — send excess cash to the vault" over the maximum and "Drawer low — get cash from the vault" under the minimum (`drawer_limit_warning()`). The maximum is crossed in about one shift in four with the player's line as it is (simulated: 25% of shifts go over at some point, 21% are still over at clock-out; over $4,000 in under 1%); customers alone can't take the drawer under the minimum. Transfers happen at the vault door under dual control (see The vault door below; the drawer panel says so): **Send to Vault** / **Get Cash from Vault** (`VaultTransferScreen`, calling `TellerScreen.send_to_vault()`/`get_from_vault()` with the witness's name, refused without one) move whole dollars, change `VaultManager.expected_cents` by the same, are logged to history with both people ("Sold $500 to the vault — dual control: you and Walter Higgins", "Vault transfer") and leave a receipt line on the vault screen and the drawer panel; the vault screen also shows the vault's own limit warning (VaultManager) ("Sold $500 to the vault · witnessed by Walter Higgins"). The closing count's expected cash includes them, to the cent. Going over during the shift is only a warning (and the one-time `Hint.DRAWER_LIMIT`, `drawer_went_over_limit`); clocking out over the maximum is a procedure mistake (`DRAWER_OVER_AT_CLOCK_OUT_SCORE` −3, one mistake toward reports). The shift summary puts transfers on the opening-count line and any breach on its own line, explaining that limits keep less cash at risk.
- **Clock-out gate (B2)**: only once every customer of the shift is handled (served, left, or abandoned); otherwise the error names what's left. The closing count grades Perfect +10 Score/+2 Reputation, Minor +5/0, Major −5/−5; Perfect/Minor are scaled by the share of the shift's customers actually served (zero if none).
- **Shift summary**: opening-count line, drawer and customer sections (with the ID line: "ID checks: 3 checked · 1 bad ID caught · 0 skipped", plus bad IDs accepted and valid IDs refused when there were any), and a "This shift" total.

## Loan Officer (`loan_officer_screen.gd`, `loan_review_screen.gd`, `LoanApplication`)

Unlocked at 500 XP / 40 Reputation. A shift is 3 applications (`APPLICATIONS_PER_SHIFT`); each is approved, rejected or counter-offered once the credit check has been run (decisions stay locked until then) and graded BEST/PARTIAL/BAD/WORST against its risk assessment (+10/+3/−3/−10 Score). DTI is monthly debt payments ÷ monthly income (B9). Closing an application without deciding keeps it pending. The player works Loan Desk 1: while they're clocked in its staff member walks to the break room in the conference room and back, and Loan Desks 2 and 3 keep deciding throughout. Meanwhile a **cover teller** works the Player Teller Window (see NPC coworkers).

## The vault door: dual control (`scripts/world/vault_door.gd`, `vault_dual_control.gd`, `scripts/ui/vault_transfer_screen.gd`)

No vault action happens with one person present. The vault door (`VaultDoor`, an `Interactable` in front of the safe inside the Vault room, E) is where a teller on shift transfers cash (`VaultTransferScreen`) and a Branch Manager on shift reconciles the vault; off shift it does nothing (`VAULT_NEEDS_SHIFT_TEXT`). Pressing E there has `VaultDualControl` (`teller_room.vault_control`) call a witness from `teller_room.vault_witness_candidates()` (everyone placed at a desk, and the cover teller, each with their teller window line, or none at a loan desk) by `choose_witness()`: an idle staff member first (in the break room, at a loan desk, or at a window with nobody being served and an empty line; the nearest to the door), otherwise the teller with the shortest line (then the nearest), who finishes the customer at the window first; never anyone already walking or the staff of a closed line. With nobody available: "No one is free to witness the vault right now." and the vault stays shut. The witness walks (`route_to_vault()`: up to the aisle behind the desks, along it to the vault's door gap and in, or out of the break room first) to `VaultWitnessSpot`; while they come the room shows "Dual control: the vault needs two people. Waiting for [Name]…" (`desk_notice`, and the door's prompt), and the action opens only once they're there and the player still is (walking away calls it off). Their window pauses meanwhile (`NpcCustomerLine.paused_for_vault`): the line keeps its customers (and takes new ones), unserved, and patience keeps running, so a long wait can cost abandonments; a loan desk's worker pauses because its staff member isn't at the desk (`StaffNPC.State.AT_VAULT`). When the vault screen closes they walk back the way they came and resume; `witness_returned` reports their game minutes away (the Branch summary). A one-time hint (`Hint.VAULT_DOOR`) comes the first time the player uses the door. Mid-shift state, never saved.

## Branch Manager (`branch_manager_screen.gd`)

Unlocked at 1500 XP / 60 Reputation, granted at clock-out if earned mid-shift, with one "Letter of Promotion" (`discipline_letter_screen.gd`) that also clears the disciplinary record, and a one-time orientation letter on the first Branch Manager clock-in. After promotion the Player Teller Window becomes the staffed **Teller Window 3** (`Window3Line` on the player's lane), every loan desk's staff stay at their desks, and the Player Teller Window and Loan Desk 1 only show "[staff] is working…". The hub offers:
- **Staff Scheduling** (`staff_scheduling_screen.gd`): assign staff to desk slots. One auto-sizing `PanelContainer` (600 px wide): the roster scrolls in a capped-height area with wrapping entries, and the desks sit in two columns (teller windows left, loan desks right), with a one-line confirmation ("Schedule confirmed — 6 of 6 desks staffed.").
- **Approvals** (`approvals_screen.gd`): override a loan decision or flag a teller record for retraining.
- **Cash Orders** (`cash_orders_screen.gd`, `CashOrdersScreen`): order cash in from the Federal Reserve Bank or ship excess out, in straps of $100 notes ($10,000 each), for delivery at opening on the next business day; one order a day. Shows the vault's expected total, its limits, pending orders and a forecast for tomorrow's close; each order is logged to history.
- **Vault Reconciliation** (`vault_reconciliation_screen.gd`): once per shift, required before clock-out, graded against `VaultManager.expected_cents` (the starting total moved by the teller's transfers). Under dual control it's done at the vault door with a witness (`open_vault_reconciliation()`, from the room); the hub's button is disabled and says so (`VAULT_AT_DOOR_TEXT`). Closing the count closes the screen (`vault_visit_closed`), and the history entry names both people.
- **Staff Review** (`staff_review_screen.gd`, `StaffReviewManager`): every staff teller mistake and every staff loan decision not graded BEST becomes a review item. Severity stays hidden until the manager decides: Serious (wrong-account mistake, WORST loan) → Issue Report; Minor (other mistakes, BAD loans) → Give Feedback, or Issue Report once that person has had 2 feedbacks; Acceptable (PARTIAL loans) → Excuse. Fair calls +3 Score; unfair reports −3 Score/−1 Reputation; serious items left unreviewed at clock-out −2 Reputation each. At 3 reports the manager can terminate a staff member: their desk becomes unassigned and its line closes.
- **Hire Staff** (`hiring_screen.gd`, `HiringManager`): shown only while a desk is vacant (unassigned after a termination or on the schedule), naming the desk(s); usable while clocked in. Each vacancy gets 3 candidates for the desk's role, named from `StaffCandidatesData` (not the customer pool) with a one-line background and hidden 1-10 stats: one strong (all 7-9), one average (all 5-6), and one weak in the stat that matters at the desk (1-2): reliability for a teller, skill for a loan officer, with the other of the two looking fine (5-7). Their order is shuffled. Candidates are ranked by `StaffCandidate.rating()`, which reads only the stats the desk's formulas use: for a teller the average of speed and the weaker of skill and reliability (service time, `mistake_chance()`); for a loan officer the average of skill and speed (`loan_correct_chance()`, decision pace). The manager asks 3 questions from `InterviewQuestionsData`, the same for all three and including at least one with an instant-reject answer, one at a time. Answers are chosen when the candidates are generated (`pick_answer()`), from that rating pulled halfway towards the weakest role stat, so a weak teller's or weak loan officer's weakness shows in poorer answers. Red flags stay tied to reliability for either role: at reliability 2 or lower, a candidate gives a question's instant-reject answer 50% of the time. Stats and scores stay hidden until a hire, whose card reveals the stats with feedback specific to the role. Grading compares the hire with the other two by rating: best +6 Score/+1 Reputation, middle +1/0, weakest −4/−1, a red-flag answer −6/−2 regardless (XP ×10 on positive Score only). Hired staff join the roster at that desk and work with the usual formulas. Reject All scores nothing, and new candidates come at the next clock-in. Candidates for a desk filled some other way are dropped.
- The shift summary adds report-only "Branch" (each desk's staff work this shift, then "At the vault: Walter Higgins 6 min": staff time away witnessing the vault, `shift_vault_minutes`) and "Staff Review" sections.

## NPC coworkers (`scripts/npc/staff_npc.gd`, `npc_customer_line.gd`, `npc_loan_desk_worker.gd`)

`teller_room.gd` places a `StaffNPC` at each staffed desk from `ScheduleManager`. Teller Windows 1/2 (and 3 after promotion) serve their own `NpcCustomerLine` (extends `CustomerQueue`: regular customers only, no per-shift cap, up to 3 waiting, arrivals every 12–18 s), with service time and mistake chance from the staff member's stats. **Cover teller** (`teller_room.gd`, `cover_npc`): while the player is clocked in at Loan Desk 1 (before promotion, and not mid teller shift), `ScheduleManager.cover_teller()` (the first Teller-role roster member not at a desk: whoever would take Teller Window 3 at promotion, Nina Ortiz by default; another free teller if not; nobody if none) walks from the break room to the Player Teller Window and serves `Window3Line` as a staff window (slot "Player Teller Window": opening hours, up to 3 waiting, no complaints, STAFF records, today's staff customers). The window then says "[Name] is covering this window while you work the Loan Desk." (prompt and notice) instead of opening the teller screen. At clock-out the line winds down (`NpcCustomerLine.wind_down()`): no new arrivals, waiting customers move to Teller Window 1 or 2 if there's room (`CustomerQueue.take_customer()`) or walk out, the customer at the window is finished (`wound_down`), and the cover teller walks back to the break room and goes. A promotion granted at that clock-out hands the window and its line straight to Teller Window 3's staff member; a demotion brings the cover back. Nothing is saved: it's mid-shift state in the room. An `NpcLoanDeskWorker` per loan desk (`slot_name`; `teller_room.loan_desk_workers`, Loan Desk 1's is `loan_desk_worker`) decides loan applications in the background; only Loan Desk 1's pauses, while the player works it. NPC work changes real (staff-line) accounts but never the player's Score, Reputation, XP or drawer; it's logged as STAFF records.

## Character art (`ART.md`, `tools/art/generate_characters.py`)

Every character uses one format: 16×24 frames, six per direction sheet (down, up, side; left is side mirrored), idle frames 0–1 at 2 fps and walk frames 2–5 at 8 fps, in a `<name>_frames.tres`. All art is original. The player and the three customer designs are lym221-not's. The rest is generated from them by `tools/art/generate_characters.py` (standard-library Python; `--check` verifies the committed art is current). `ART.md` has the credits and how to regenerate.
- **Staff** wear a bank uniform (blue blazer, white shirt front, charcoal trousers, gold name tag) built on the player's body, with no tint or badge. Each has a look (`StaffMember.look`, a `StaffLooks` id) with its own hair style, hair colour and skin. The six roster members have fixed looks (`staff_01`–`06`). A hire gets one of `StaffLooks.HIRE_LOOKS` (`staff_07`–`10`) in `ScheduleManager.hire_staff()`, preferring one nobody wears, and it's saved with them.
- **The Regional Manager** (`StaffLooks.REGIONAL_MANAGER_LOOK`, `regional_manager`): the player's body and suit recoloured light grey with a burgundy tie and silver hair, no uniform or name tag. Not one of the staff looks.
- **Customers** pick from 12 looks (`CustomerNPC.CUSTOMER_FRAME_SETS`): the three designs plus three recolours of each.
- **Impatience** shows as a pixel speech bubble above the customer (`PatienceIndicator`, drawn above the room): hidden, then "…" at 40% of their patience, "!" at 65% and "!!" at 85%. The sprite's own colours never change.

## Reports and termination (`ReportManager`)

Every 2 mistaken teller customers = 1 written warning (a letter), and so does Reputation falling to 0 for a Teller or Loan Officer (`ZERO_REPUTATION_REASON`, "Customer satisfaction has fallen to zero", in the player's role, with no customers listed; once per fall, see ReputationManager); 3 reports = termination (2 while on probation; `ReportManager.report_limit()`), with a full-screen letter, then, with the interview off, game over: the current save slot is cleared (only that one) and the player lands on the slot screen (with it on, the interview; see Flow). Warning letters on probation say so. Reports carry across shifts and roles. Branch Managers are exempt: promotion clears the record, and the Regional Manager reviews them instead. A demotion back to Loan Officer makes reports apply again, from none.

## Regional Manager (`scripts/autoload/regional_manager.gd`, `RegionalManager`)

- **Schedule**: a review every `REVIEW_INTERVAL_DAYS` (5) business days as Branch Manager (days are business days, so weekends and holidays never count). The promotion day doesn't count (promoted on Day 10: reviewed at the End of Day 15), then every 5 days (`next_review_day()`). Days as a Teller or Loan Officer never count. On review day the Regional Manager (a `StaffNPC` in the generated `regional_manager` look: grey suit, silver hair, no uniform) walks in from the entrance at 10:00 AM, stands outside the Manager's Office and walks out at 11:30 (`teller_room.gd`, `_update_regional_visit()`; a room loaded mid-visit has them standing there; going home ends the visit). The review runs at that day's End of Day (`teller_room.show_end_of_day()` → `run_review()`); its letter (the shared letter screen, scrolling) comes before the summary, which follows once the letters are acknowledged.
- **The window** (since the promotion or the last review, collected only while Branch Manager): vault results by day (`branch_manager_screen.gd` → `note_vault_result()`), serious staff-review items reviewed, excused, closed as ignored at clock-out (`note_serious_ignored()`) or still waiting at the review, reviews and unfair reports (`StaffReviewManager.review_decided`), staff work and mistakes (`HistoryManager.staff_record_added`), customers who gave up at staffed windows (the staff lines' `customer_abandoned`), vacant desk-minutes during opening hours (`sample_vacancies()`, which also covers hours skipped by going home), and hire verdicts (`HiringManager.staff_hired`).
- **Rating** (`evaluate()`): each area scores 0–100 or isn't rated when there was nothing to judge; the overall score is the weighted average of the rated areas. Weights: vault 25, serious errors left unreviewed 20, fairness of reports 25, serious errors excused 10, staff mistake rate 5, staff-line abandonment 5, vacant desks 5, hiring 5. Vault: each of the 5 days scores its best count (Perfect 100, Minor 70, Major 30, none 0). Unreviewed −25 each, unfair reports −40 each, excused −50 each. Mistake rate 100 at ≤10% down to 0 at 40% (rated from 10 pieces of work). Abandonment 100 at none down to 0 at 25%. Vacancies −2.5 per desk-hour. Hires: best 100, middle 60, weakest 20, red flag 0. Bands: Exceeds ≥ 92, Meets ≥ 80, Needs Improvement ≥ 50, else Unsatisfactory. A day spent going home without working has no vault count and leaves serious items waiting, so it lowers the score by itself.
- **Consequences** (`apply_consequences()`): Exceeds +15 Score (+150 XP) and +3 Reputation and removes one regional warning; Meets nothing; Needs Improvement one warning; Unsatisfactory one warning and −5 Reputation.
- **Reputation 0**: a Branch Manager whose Reputation falls to 0 gets one regional warning instead of a report, with a "Regional Warning — N of 3" letter (`zero_reputation_warning`; once per fall, see ReputationManager). If it's the third, the demotion waits for that day's End of Day (`is_demotion_due()`, `demote_if_due()` from `teller_room.show_end_of_day()`), before the summary and instead of any review, so it never happens mid-shift; saved warnings may be 3 for that. If an Unsatisfactory review's Reputation cost is what reaches 0, its warning counts and the review demotes at once.
- **Demotion** at 3 warnings (`WARNINGS_FOR_DEMOTION`): a "Notice of Demotion" letter after the review's, and the player is a Loan Officer again (`XPManager.demote_branch_manager()`): ScheduleManager closes Teller Window 3 (its staff member stays on the roster, unassigned), ReportManager makes reports apply again from 0, and the room closes Window3Line and hides the Branch Manager desk, so the Player Teller Window and Loan Desk 1 work for the player again. Staff, hires and staff reports stay; review items still waiting are closed as "closed at demotion" with no penalty (`StaffReviewManager`), so a re-promoted manager doesn't answer for them. Warnings reset. Promotion again needs 500 more XP than at the demotion and Reputation 60, through the usual flow and letter (the orientation isn't shown twice).
- **HUD**: "Next review: Day N · Warnings 1/3" while Branch Manager (`status_text()`).

## Save and load (`scripts/util/save_game.gd`, `SaveGame`; `scripts/ui/start_screen.gd`)

- **Slots**: one JSON file per slot, `user://career_slot_<n>.json` (`SaveGame.slot_path()`, named from `SaveGame.prefix`). Choosing a slot calls `SaveGame.use_slot()`: `current_slot` and `path` are that slot's, so `save()`, `read()` and `delete()` only ever touch it (`read_slot()` reads any slot without choosing it). At the menu `leave_slot()` clears them (`path` empty: nothing saves). The old single save, `user://career.json` (`legacy_path()`), is moved into Slot 1 when the menu opens (`migrate_legacy_save()`), only if Slot 1 is empty; it's never written again.
- **What**: the whole career, as JSON at `SaveGame.path` (the current slot's file) with `FORMAT_VERSION` (1). That covers every autoload's career state: Score, Reputation, XP and unlock/promotion flags, reports, pending mistakes and probation, every account and balance, the vault's expected total, the schedule (by staff name), hired and dismissed staff, staff reports and feedback counts, the review queue, waiting job candidates with their interview progress and rejected vacancies, history (the 200 staff-record cap still holds on load), the orientation flag and hints, the game clock (day, time of day and the calendar's start date) and the business day's totals (after-cutoff transactions included), and the Regional Manager's review (warnings, the review window and its data, and a demotion's re-promotion XP target). A Branch Manager from a save without review data starts a window from the loaded day. Mid-shift state (queues, drawers, screens, desks on shift) is never saved, so a loaded career starts off shift. `Account`, `DecisionRecord`, `DisciplinaryReport`, `StaffReviewItem`, `StaffMember` and `StaffCandidate` are saved from their exported properties (`resource_to_dict()`/`fill_resource()`), so a new exported field is saved automatically.
- **When**: on being hired (with the interview off, as soon as a new game starts, `start_screen.gd`; with it on, on Hired or Hired on Probation, `interview_screen.gd`), so quitting before the first clock-out continues the career and probation can't be escaped by re-taking the interview; and (`teller_room.save_career()`) at every clock-out (teller, Loan Desk 1, Branch Manager's new `shift_clocked_out`), after a promotion, and after the one-time orientation letter. The Probation Complete letter comes at a teller clock-out, so that save covers it. Writes go to a `.tmp` file that is then moved over the save.
- **Slot screen**: a filled slot runs `SaveGame.restore()` (a `CareerReset` and then each `load_data()`, with Reputation before XP so no unlock fires again) and loads the room. An empty slot starts a new career (straight into the room as a Teller with the interview off, or the interview with it on). "Back to Main Menu" in the pause menu saves first off shift (`teller_room.save_career()`); on shift it asks and doesn't save.
- **Robustness**: `SaveGame.read()` reports MISSING, OK, CORRUPT (not JSON, or the wrong shape) or WRONG_VERSION, and never errors. An unreadable slot says so on its button; clicking it offers a new game there, moving the bad file to `career_slot_<n>.json.bad` first. Values are read through typed getters (`int_of()`, `dict_of()`, ...), so a mistyped value falls back to its new-game default. Game time built up from frame deltas (`GameClock.minutes`, the review window's vacant desk-minutes) is saved through `SaveGame.time_for_save()`, snapped to 1/64 of a game minute: Godot's JSON parser doesn't always read a full 17-digit float back exactly, which once failed a round-trip test on CI.
- **Guard**: only the real game flow may write, move or delete the real saves (every slot file named from `SaveGame.real_prefix`, and from `REAL_PREFIX` whatever `real_prefix` says). Paths are compared as files on disk (`_disk_path()`: globalized, simplified, case-insensitive on Windows), so another spelling of a real save is refused too. The start screen enables it with `allow_real_save()`. Anything else that still points `path` at one is refused with a warning (see the rule under Tests and CI), the old single save is never written (only moved into Slot 1), and nothing saves with no slot chosen.
- **Termination** deletes the current slot's save (that slot only) as soon as the letter appears (so quitting at the letter can't undo it) and again when its button is pressed ("Back to Save Slots", or "Apply for a new job" with the interview on). `SaveGame.save()` refuses while `ReportManager.is_terminated`.

## Letters (`discipline_letter_screen.gd`)

Every letter (written warnings, termination, promotion, orientation, probation complete, staff termination) uses one shared panel: centred, at most 72% of the 648px window tall (`MAX_HEIGHT_SHARE`). A long body scrolls inside it (mouse wheel, scrollbar or dragging) while the title, sender and button stay visible, and a short letter shrinks to its text.

## HUD, prompts and hints (`scripts/ui/hud.gd`, `scenes/ui/hud.tscn`, B4)

The `HUD` CanvasLayer (layer 2, above `UI`) shows the game day and time (`GameClock.hud_text()`), role, Score, Reputation, XP, Reports (with the probation line, e.g. "Probation — 1 of 3 clean shifts", while on probation, and the Regional Manager's "Next review: Day N · Warnings 1/3" while Branch Manager) and shift status in a top-right column that stays clear of every centred screen at 1152×648. Below it are the notifications: the low-reputation warning stays up while Reputation is low; a role-unlocked notification shows once when the unlock happens (XPManager's signal, so never after loading a save) and fades after 5 s (`show_unlock_notification()`). Then first-run hints with a "Got it" button. The hint text sits in a `ScrollContainer` sized to the text but never taller than the room left in the column at the 648 px design height (`_fit_hint()`, `COLUMN_BOTTOM_MARGIN`), so with every notification up a long hint scrolls instead of running off the window; `b4_hud_test.gd` lays out every hint in that worst case. A permanent controls line in the bottom-left corner (`Hud.controls_text()`, e.g. "E — interact · Z — zoom · Esc — menu", key names from the InputMap; `InputPrompts.key_for()` names Escape "Esc") sits clear of the column and every centred screen. It's visible with or without a desk screen open, and hidden while the termination letter is up. The "E — …" interaction prompt appears below whichever interactable the player stands at (`teller_room.interaction_prompt_text()`), or says why a desk can't be used (e.g. "Loan Desk 1 — unlocks at 500 XP and 40 Reputation"). It's hidden while a screen is open. Key names come from the InputMap (`InputPrompts.key_for()`).

## Development workflow

Play by opening the project in the Godot 4.7 editor and using Play/Run.

### Tests and CI

Tests use **gdUnit4 v6.2.1** (`addons/gdUnit4/`, the addon's own self-tests left out). Suites live in `tests/` (`*_test.gd`, extending `GdUnitTestSuite`). Suites that drive the real room extend `tests/support/teller_room_suite.gd`: a fresh `teller_room.tscn` (`room: TellerRoom`; `adopt_room()` after a scene change loads another) and a fresh career per test, test save files instead of the real ones (`SaveGame.prefix` = `TEST_PREFIX`, `user://test_career`, playing Slot 1, `TEST_SAVE_PATH`; every test slot file and the test "old single save" are removed before and after each test, so tests never touch the real saves), the interview switch reset to its default (`use_interview_setting()` sets it for one test), a seeded RNG, the player's line with every ID valid and no account openers (`_fix_id_rolls()`; `kyc_test.gd` sets the real chances), and helpers to clock in/out, spawn customers with fixed requests and a valid ID (`give_id()`, `spawn_opener()`), press the teller buttons (`check_id()`, `refuse_service()`, `open_account()`; `serve_correctly()` checks ID when needed; `send_excess_to_vault()` before a clock-out that would be over the drawer limit; `call_vault_witness()`, `vault_transfer()` and `reconcile_vault()` for the vault door (the witness's walk skipped with `StaffNPC.finish_route()`); `deposit()`/`withdraw()`/`spawn()` take dollars, like a player typing; `count_drawer()` takes cents).

Run everything locally (Git Bash on Windows):

```sh
GODOT_BIN="/c/Users/USER/Downloads/Godot_v4.7.1-stable_win64.exe/Godot_v4.7.1-stable_win64_console.exe" ./run_tests.sh
```

`run_tests.sh`:
1. Checks the generated character art is current (`tools/art/generate_characters.py --check`). The Python interpreter comes from `PYTHON_BIN`, or else the first of `python`/`python3` that runs.
2. Imports the project.
3. Checks scripts for warnings. Warnings never print when a script loads, so `tools/write_warnings_override.gd` writes `override.cfg` raising every enabled warning to Error for one run, and `tools/check_scripts.gd` compiles every script (addons excluded); the override is deleted afterwards.
4. Runs every suite in `tests/`.
5. Does two `--headless --quit-after 300` boots: the main scene (the start screen's main menu) and `teller_room.tscn` directly, so the gameplay room is boot-checked on its own, not only through tests.

It fails on stale generated art, any warning, any failing test, a failed boot, or any `ERROR:`/`SCRIPT ERROR:` line. CI (`.github/workflows/tests.yml`) runs the same script on every push and pull request with a pinned Godot 4.7.1 Linux build and Python 3.12, and uploads the gdUnit4 report. Keep the CI, local and gdUnit4 versions in step.

**Screen fit**: `teller_room_suite.layout_problems(panel)` checks a laid-out screen panel and every visible control in it: each inside the panel, inside the 1152×648 window with `WINDOW_MARGIN` (8 px) to spare, and left of the HUD column (`HUD_COLUMN_LEFT`, x 952); controls inside a ScrollContainer are checked through the container. `tests/screen_fit_test.gd` runs it on every screen that lists desks or staff, with a Branch Manager's six desks: Staff Scheduling (before and after confirming), the Branch Manager hub (with a vacancy) and its shift summary, Staff Review, Hiring (two vacancies) and the Regional review letter. A screen must be visible in the tree (its parent screen open) to be laid out.

**Rule: when you verify a fix or feature, add or update permanent tests in `tests/`.** Don't write temporary verification scripts and delete them afterwards. If something can't be reached from a test, make it injectable (e.g. `teller_room.gd`'s `debug_cheats_enabled`) rather than skipping the test.

**Rule: scripts and tests must never write to the real saves** (`user://career_slot_<n>.json` and the old `user://career.json`, named from `SaveGame.real_prefix`). Point `SaveGame` at files of their own first: room-driving suites get `SaveGame.prefix` = `user://test_career` from `teller_room_suite.gd`, and the `scratch/` screenshot scripts call `SaveGame.use_saves_named("user://scratch_shots_career")` (every slot theirs, so a slot screen or Back to Main Menu in a script can't reach a real one). `SaveGame` also refuses to write, move or delete a real save, with a warning, unless the real game flow has started (the start screen calls `SaveGame.allow_real_save()`). That covers a scene run on its own from the editor too.

**Debug shortcuts** (debug builds only: `debug_cheats_enabled`, i.e. `OS.is_debug_build()`; nothing in a release build), both through the normal unlock checks:
- **F1** (`DEBUG_UNLOCK_KEY`) maxes Reputation and adds 2000 XP, unlocking Loan Officer and Branch Manager.
- **F2** (`DEBUG_LOAN_OFFICER_KEY`) raises XP to at least 500 and Reputation to at least 50 (never lowers them), unlocking Loan Officer but not Branch Manager (which needs Reputation 60).
